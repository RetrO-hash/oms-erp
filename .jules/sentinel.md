## 2024-05-24 - Hardcoded Secrets in Config Files and Default Property Values
**Vulnerability:** The application contained hardcoded sensitive information including database passwords, Redis passwords, and OAuth RSA public/private keys in multiple `application.yml` files as default values for environment variables. Additionally, the RSA keys were hardcoded as default field values in multiple `@ConfigurationProperties` Java classes.
**Learning:** Default values in `@ConfigurationProperties` fields can override configurations if they are not explicitly loaded or if the keys do not perfectly match. It is crucial to ensure that sensitive properties have null or absent default values so that missing environment configurations fail fast rather than silently falling back to a hardcoded secure risk.
**Prevention:** Always externalize secrets completely. Use environment variables (e.g. `${SECRET_KEY}`) without hardcoded fallback values in both configuration files and Java property classes. Ensure that CI/CD pipelines and deployment scripts manage these secrets securely.
