
## 2024-05-18 - [Hardcoded Maintain Secret Key & User Input Reflection]
**Vulnerability:** A hardcoded default "skyer" secret string was used as a fallback configuration for `skyer.maintain.secretKey` property, allowing trivial override if the actual secure environment variable is empty. Additionally, the corresponding authentication exception in `MaintainEndpoint.java` directly reflected user input in the exception error string.
**Learning:** Hardcoding default string values for security configurations can unintentionally bypass secure null checks or fallback mechanics designed to ensure environment variables are intentionally populated, leaving systems with easily guessable default keys. User input reflection in exceptions risks log forging or exposing sensitive environment variables back to unauthenticated users.
**Prevention:** Avoid providing default hardcoded string values in `@ConfigurationProperties` for secrets; instead, allow them to default to `null` so proper checks (like defaulting to a random UUID when null) can be correctly invoked. Additionally, always use generic error messages for authentication and input validation failures rather than echoing the raw, unvalidated input back to users or error logging streams.
