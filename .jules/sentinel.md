## 2024-05-29 - Hardcoded Default Field Values Can Disable Secure Fallbacks
**Vulnerability:** A hardcoded `secretKey` default value in `@ConfigurationProperties` prevented the intended runtime random secure key generation from taking effect when the key wasn't explicitly configured.
**Learning:** Hardcoding default values in Java `@ConfigurationProperties` classes (e.g., `private String secretKey = "skyer";`) can silently override programmatic, secure fallback mechanisms. In this case, `StringUtils.defaultIfBlank` failed to fall back to a securely generated random key because the value was neither null nor blank, thus forcing the application to use a hardcoded default that could be exploited.
**Prevention:** For sensitive configurations where a secure fallback mechanism (like generating random keys at runtime) exists, leave the `@ConfigurationProperties` field values initialized to `null`. This allows `StringUtils.defaultIfBlank` or similar checks to correctly default to the secure mechanism if no value is explicitly supplied.
