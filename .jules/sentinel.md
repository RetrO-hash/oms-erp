## 2024-05-14 - Hardcoded Secret, Timing Attack, and Input Reflection in MaintainEndpoint
**Vulnerability:** Found a hardcoded default secret (`"skyer"`) in `MaintainProperties`. In `MaintainEndpoint`, the `secretKey` was compared using `.equals()`, which is vulnerable to timing attacks, and the authentication failure exception message reflected the untrusted user input, exposing it to log forging/XSS.
**Learning:** Default properties for secrets should be null to enforce secure generation or environment-based configuration. String equals operations are not constant-time and should not be used for comparing secrets. Untrusted input should not be directly concatenated into error logs or messages.
**Prevention:** Initialize secret configuration properties to `null`. Use `java.security.MessageDigest.isEqual()` on UTF-8 bytes for constant-time secret comparison (with null checks). Fail securely by using generic error messages (e.g., "认证失败") that do not leak or reflect user input.
