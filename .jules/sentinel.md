## 2024-05-18 - Prevent Hardcoded Secret Override via Default Fallbacks
**Vulnerability:** Found hardcoded secrets (`secretId`, `secretKey`, `jwt-key` for API signatures, `baison` integration secrets, etc.) directly in `application.yml` files and Java `@ConfigurationProperties` classes (e.g., `MaintainProperties.java`). Using hardcoded credentials in source code exposes critical security material to anyone with repository access.
**Learning:** Even if environment variables are referenced in configuration files (e.g. `${SECRET_KEY:default_value}`), the presence of a fallback `default_value` or a default field initialization in Java classes (like `private String secretKey = "skyer";`) can override or expose the secrets if the environment isn't explicitly configured or if the codebase is analyzed.
**Prevention:** Always use environment variables without hardcoded fallbacks (e.g. `${SECRET_KEY:}`) in configuration files and avoid initializing secret fields with sensitive strings in Java. The default values should be `null` or empty to ensure the application fails securely (or prompts for correct configuration) rather than running with compromised credentials.
