## 2026-07-07 - Fix exposed secret in error message and timing attack vulnerability
**Vulnerability:** In `MaintainEndpoint.java`, the system used `String.equals()` to compare the provided `secretKey` with `configKey`, which is susceptible to timing attacks. Furthermore, on failure, it threw a `RuntimeException` that echoed the user-provided `secretKey` back in the error message, leading to potential log forging, XSS, and information leakage.
**Learning:** Standard string comparisons stop at the first differing character, allowing attackers to guess keys byte-by-byte. Echoing user input in exceptions exposes systems to log forging or injection attacks.
**Prevention:** Use `java.security.MessageDigest.isEqual()` on byte arrays for constant-time comparisons when checking secrets or passwords. Ensure error and exception messages remain generic (e.g., "Authentication failed") and do not reflect user input or sensitive system data. Always check for null before calling `.getBytes()` on string configurations.
