## 2024-06-05 - Hardcoded Secrets in Config Files and Properties
**Vulnerability:** Several sensitive credentials, such as third-party API keys (`baison.key`, `baison.secret` in `skyer-order`), JWT keys, gateway signature secrets, and maintain API secret keys, were hardcoded directly in Spring Boot `application.yml` files and fallback property values in Java classes (e.g., `MaintainProperties.java`).
**Learning:** Storing secrets directly in source control exposes them to unauthorized access. By default, Spring Boot will fallback to hardcoded property values if an environment variable is missing, negating the purpose of externalized configuration. Hardcoded secrets are a critical vulnerability.
**Prevention:** Always externalize secrets using environment variables (e.g., `${SECRET_VAR:}`). Avoid setting hardcoded default values in configuration classes (use `null` instead) so that the application fails securely (or falls back to secure dynamically generated logic, as seen in `MaintainEndpoint`) rather than silently using an insecure default credential.
